Les trois derniers étaient refusés avant la correction des chemins `\` dans les archives.

Corrections issues de ces essais :

- **Dossier de travail des plugins natifs :** un exécutable démarre désormais dans son propre dossier (`bin/`, `plugin/`…), comme sous Stream Dock. C'était la cause de l'échec de Gizmos sur le D6 : ses scripts sont appelés par `../cmd/scripts/…`, introuvables depuis la racine du plugin. Les plugins Node.js restent lancés à la racine.
- **`CodePath` sans extension contenant des points** (`com.vendor.tool` → `com.vendor.tool.exe`), comme Stream Deck sous Windows.
- **Archives créées par l'ancien DistributionTool** (séparateurs `\`) : acceptées après normalisation ; les chemins `..`, absolus ou avec lecteur restent refusés.

Non vérifié : effet réel de ces plugins sur le D6 (à refaire, Gizmos en premier), actions nécessitant un service tiers (Discord, Streamlabs, SignalRGB, Govee, Bitwarden connecté), autres actions de chaque plugin.

### Corrections issues du banc

- **Import sans redémarrage :** le catalogue du gestionnaire de plugins était figé au lancement ; un plugin importé depuis le magasin restait « introuvable » jusqu'à la relance de DeckForge. `Manager::set_catalog` met désormais le catalogue à jour après l'import et démarre les touches déjà liées (test `plugin_imported_at_runtime_starts_without_restart`).
- **Validation sans effets locaux :** l'App isolée de validation partait de la configuration par défaut, dont la touche 1 envoie Ctrl+C et la touche 2 Lecture/Pause. Valider un plugin envoyait donc ces entrées au système (et faisait tomber la machine de CI GitHub). Les macros et touches média sont désormais vidées avant tout appui virtuel (test `validation_bench_never_runs_default_macros_or_media_keys`).

## Essai positif distinct : OpenAction Counter v1.0.1 — 18 octobre 2026

- Archive de release `me.amankhanna.oacounter.zip`, SHA-256 `f04e0724188468e450633a49d15ee98ab0400faa2197332cfcf80278d0c54e47`. Manifeste et code source examinés ; le binaire de release tiers est épinglé par hash, sans preuve de compilation reproductible. Aucun code OpenDeck GPL copié.
- **Automatisé, hors matériel** : `plugin_import::import_archive` a installé l'archive dans un répertoire temporaire ; le vrai exécutable Windows a reçu `keyUp` via le Host et renvoyé `setSettings` (`value=1`) et `setTitle` (`1`). Un second test opt-in a traversé l'App isolée, les événements d'appui virtuels et observé le titre `1`. Tests réussis au commit `5ffca5d`, lancés explicitement avec l'archive épinglée (non commise).
- **Essai dans la copie réelle avec D6** : copie neuve `Desktop/DeckForge-0.7-counter-test`, binaire issu du build courant et package décompressé dans `plugins` ; configuration indépendante à un seul bouton actif (touche 1, compteur persisté). Après un appui demandé à Hatim, trace opt-in : un `keyDown` et un `keyUp` envoyés, puis `setSettings` et `setTitle` reçus du plugin. La valeur sauvegardée dans la configuration de la copie est passée de `0` à `1` ; Hatim a confirmé voir `1` sur la touche physique. C'est un effet observé d'une action tierce, pas seulement une trame envoyée. **L'import UI de l'archive n'a pas été testé dans cette copie** (extraction contrôlée) ; le chemin d'import logiciel est éprouvé par les tests automatisés.
- Aucun Property Inspector HTML ouvert ; aucun effet audio, compte ou service réseau externe sollicité (hors WebSocket local requis au plugin). Le redémarrage du plugin avec réglages persistés reste non vérifié. L'application habituelle n'était pas en cours d'exécution lors de la préparation et n'a pas été modifiée. `CloseMainWindow()` a masqué la fenêtre sans quitter le processus (comportement « fermer vers la zone de notification » activé par défaut dans `src/catalog.rs`, géré dans `src/ui.rs`), pas une preuve de blocage. Après vérification de la valeur sauvegardée `1`, l'arrêt forcé de la **copie uniquement** a terminé l'hôte et son enfant. Aucun DeckForge GUI ne restait actif.
