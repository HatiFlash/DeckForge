# Contrats Elgato : comparaison OpenDeck / DeckForge (18 octobre 2026)

Références de lecture seule : OpenDeck commit `772189ca74c89a10bad219b67de620ecb07bf1f6` (`src-tauri/src/plugins/mod.rs`, `webserver.rs`, `src-tauri/src/events/{inbound,outbound}/` et `PropertyInspectorView.svelte`) ; OpenAction API docs commit `ffe2564bd42f54b19443cf1dac821adf6a85a848` (`src/api/registration.md`, `src/overview.md`) ; SDK Elgato, rubriques WebSocket Plugin, Property Inspector et Settings. OpenDeck est GPL-3.0 : ses mécanismes sont étudiés, **aucun de ses fichiers ni fragment de code n'est copié** dans DeckForge MIT.

## Diagnostic fonctionnel borné

Le test automatisé `registered_client_receives_key_events_for_distinct_contexts` fait s'enregistrer un client WebSocket loopback, reçoit réellement `keyDown` pour deux contextes et `keyUp` pour le premier, vérifie action/contexte/appareil/controller/resources, puis reçoit dans l'hôte une commande `setTitle` sur le second contexte. Il utilise `plugin_runtime::event`, **pas** un plugin tiers ou le circuit HID/App complet. Test ciblé vert ; build Windows complet : 298 tests applicatifs réussis, 1 ignoré, 9 MCP réussis (script `tools/Build-Windows.ps1 -Action All`, code de sortie 0). Aucun changement de production dans ce commit.

Essai matériel D6 autorisé sur copie isolée : Gizmos s'enregistre ; `deviceDidConnect`, `willAppear`, `titleParametersDidChange` puis `keyDown` et `keyUp` ont chacun une ligne `host->plugin sent` (écriture WS locale réussie). Le journal HID contient deux paires appui/relâchement espacées d'environ dix secondes : les deux paires WS ne démontrent donc pas une duplication pour un seul appui. Aucune commande Gizmos→hôte après enregistrement, et aucune nouvelle image dans `Pictures/Screenshots` pendant la fenêtre observée (800 fichiers avant et après). Le script installé de l'action `ScreenshotFullScreenSave` vise Win+Impr. écran ; l'absence d'image dans ce dossier ne démontre ni que le processus a reçu/traité la trame, ni tous les effets possibles du script. Copie de test arrêtée ; application habituelle relancée seule et répondante ; aucun descendant Gizmos de la copie encore actif.

## Tranches suivantes, sans exception par UUID

1. **Exécution de l'action** : distinguer trame écrite, traitement plugin, lancement/erreur d'un enfant et effet attendu, avec télémétrie opt-in bornée/censurée ; comparer à un plugin tiers ouvert à résultat déterministe après audit de son code et accord d'exécution. Le modèle officiel Elgato Counter est une source MIT, mais doit être généré/compilé ; sa PI charge un script externe : ne pas la lancer en prétendant à un essai hors ligne.
2. **Cycle réglages/contextes** : tests de contrat pour deux instances, changements de paramètres et acheminement `didReceiveSettings` entre plugin et PI ; éviter de confondre mise à jour de réglages avec disparition/réapparition de touche.
3. **PI HTML** : évaluer WebView2 sur Windows avec profil éphémère, navigation et accès fichiers contrôlés, pont limité et session WS/HTTP vérifiée. Le proxy `plugin_validation_proxy.rs` reste sous `cfg(test)` et présente des défauts de protocole/quotas ; ne pas l'activer comme sandbox. Vérifier aussi l'ouverture par handle des fichiers de `plugin_http.rs` (course entre vérification du chemin et lecture).

Les processus natifs de plugins gardent les droits Windows de l'utilisateur ; la sécurité de leur WebView n'est pas leur sandbox. Ni compatibilité universelle ni réussite de Gizmos ne sont revendiquées.
